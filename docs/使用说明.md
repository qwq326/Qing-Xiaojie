# 晴小姐 使用说明

## 一、文件与端口

| 位置 | 作用 |
| --- | --- |
| `launcher\启动晴小姐.bat` | 一键启动（推荐双击） |
| `launcher\停止晴小姐.bat` | 停止全部服务 |
| `launcher\检查端口占用.bat` | 端口诊断报告 |
| `launcher\安装桌面快捷方式.bat` | 在桌面创建「启动」「停止」快捷方式 |
| `adapter\qing_tts_adapter.py` | OpenAI 兼容 TTS 适配器 |
| `config.ps1` | **本机配置**（由 `config.example.ps1` 复制而来，不入库） |

服务与端口：

| 服务 | 端口 | 就绪标志 |
| --- | --- | --- |
| GPT-SoVITS WebUI | 9874 | 打开网页能看到界面 |
| GPT-SoVITS 推理服务 | 9872 | 日志出现 Gradio 的 Running on local URL |
| 晴小姐 TTS 适配器 | 9880 | 浏览器访问返回 `Qing TTS adapter is running` |
| SillyTavern | 8000 | 能打开聊天界面 |

## 二、首次配置

1. 安装 GPT-SoVITS 整合包（必须含 `runtime\python.exe`）
2. 下载模型权重 → 放进 `GPT_weights_v3\` / `SoVITS_weights_v3\`
3. `copy config.example.ps1 config.ps1`，填好 `GptSoVITS`、`GptWeights`、`SovitsWeights`、`SillyTavern`、`Node`
4. 双击 `launcher\启动晴小姐.bat`

启动器会先做存在性检查，缺文件会直接列出来并退出，不会启动半套服务。

## 三、日常使用

- **启动**：双击桌面「晴小姐AI - 启动」，或 `launcher\启动晴小姐.bat`
- **停止**：双击桌面「晴小姐AI - 停止」，或 `launcher\停止晴小姐.bat`
- **只看状态**：`launcher\检查端口占用.bat`

启动顺序是固定的：WebUI → 推理服务 → 适配器（等推理服务 HTTP 就绪）→ SillyTavern。
全部就绪后会自动打开网页，并在窗口末尾打印 `Final status` 表格。

注意：

- 不要连续双击两次启动器 —— 有单实例锁，第二个会提示后退出
- 启动器启动的子服务窗口**不要关**，关掉窗口等于停掉该服务
- 推理服务没就绪时适配器不会启动（避免 SillyTavern 收到 `ECONNREFUSED 9880`）

## 四、日志

日志目录由 `config.ps1` 的 `LogDir` 决定，每次启动生成：

```
gpt_sovits_main_<时间>.log
gpt_sovits_inference_<时间>.log
qing_tts_adapter_<时间>.log
sillytavern_<时间>.log
port_report_<时间>.txt          # 启动时的端口快照
ports_<时间>.txt                # 检查端口占用时生成
```

日志为 UTF-8，可用 VS Code / Notepad++ / 新版记事本打开。启动失败时启动器会打印对应日志的最后 30 行，不用再去翻窗口。

## 五、常见故障

| 现象 | 处理 |
| --- | --- |
| 9872 起不来，日志有 `Invalid port ':1]'` | `NO_PROXY` 里含 `[::1]`/`::1`，启动器已自动清理；手动跑时需自己清 |
| 9880 拒绝连接 | 先确认 9872 就绪；再看 `qing_tts_adapter_*.log`；参考音频/权重路径错误也会导致退出 |
| 音色发飘、含糊 | 调低 `top_p` / `temperature`（见 `config/tts_params.json`） |
| 音量很小 | 参考音频太轻；适配器会做响度归一，但仍建议换一条清晰的参考音频 |
| 端口被别的程序占用 | 启动器只提示不杀；用 `检查端口占用.bat` 看 PID 后自行处理 |
| 首次启动极慢 | 推理服务首次加载可能 10 分钟以上，启动器超时 30 分钟，耐心等日志 |

## 六、启动器做过什么修复（历史记录）

这些问题在早期版本里都出现过，现已修好，记录在此方便排查：

1. 端口被占时不再静默跳过，会显示占用者 PID / 进程名 / 完整路径
2. 每个服务独立日志，启动失败不再一闪而过
3. 推理服务超时由 8 分钟放宽到 30 分钟
4. 清理 `NO_PROXY` 中的 `[::1]`/`::1`，并设置 `GRADIO_ANALYTICS_ENABLED=False`（httpx 0.27 的坑）
5. 日志强制 UTF-8，中文不再乱码
6. 单实例锁：双击两次不会起两个启动器
7. 启动期看门狗不误判；不再把“端口已监听但 HTTP 未就绪”的自有进程当僵尸杀掉
8. 停止脚本先停看门狗，再清重复进程，避免“停完又活”
9. 适配器关闭 `SO_REUSEADDR`，Windows 上不会有两个适配器同时绑定 9880
10. 启动器改用 netstat 端口缓存 + TCP 就绪探测：全部在线时检查约 0.6 秒
